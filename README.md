# Online Retail Customer Analytics

End-to-end portfolio project using **Python, PostgreSQL, SQL, and Tableau** on the UCI Online Retail II workbook.

**Customer Segmentation, Churn Risk, and 90-Day Customer Value Analytics**

The project does not claim full customer lifetime value. The regression target is customer revenue during the next 90 days.

## Required end-to-end route

This ZIP is intentionally **source-only**. It does not contain the raw workbook,
processed transactions, model artifacts, or a pre-generated Tableau dataset.
You add the raw workbook locally and run the pipeline so the portfolio has a
real, traceable flow through Python, PostgreSQL, SQL, and Tableau.

```text
Raw Excel
→ Python cleaning
→ clean transaction CSV
→ PostgreSQL retail.transactions
→ SQL customer and reporting features
→ Python models written back to PostgreSQL
→ SQL unified Tableau view
→ one final Tableau CSV
```

After a successful run, connect Tableau Public only to:

```text
data\outputs\tableau_dashboard_dataset.csv
```

That file is generated by `src\06_export_tableau_csv.py` directly from
`retail.tableau_dashboard_dataset`; it is not supplied in advance.

## Validated dataset results

| Metric | Validated result |
| --- | ---: |
| Raw rows | 1,067,371 |
| Clean transaction rows | 793,609 |
| Customers | 5,878 |
| Orders | 36,969 |
| Countries | 41 |
| Clean revenue at source precision | £17,685,460.638 |
| Display revenue rounded to cents | £17,685,460.64 |
| Date range | 1 Dec 2009–9 Dec 2011 |

Cleaning removes exact duplicates, cancelled invoices, missing customer IDs, nonpositive quantities, nonpositive prices, and invalid transaction identifiers. Three-decimal source prices are preserved. This prevents legitimate £0.001 lines from becoming zero-revenue rows during PostgreSQL loading.

## Validated model results

Classification uses a temporal split:

- training snapshots: 1 Jun 2010–1 Mar 2011;
- validation snapshot: 1 Jun 2011;
- untouched test snapshot: 1 Sep 2011;
- observation window: 180 days;
- prediction window: 90 days;
- churn definition: no order during the following 90 days.

Logistic Regression was selected by validation ROC-AUC, then refit on training plus validation data and evaluated once on the test snapshot.

| Test metric | Result |
| --- | ---: |
| ROC-AUC | 0.7374 |
| PR-AUC | 0.6245 |
| F1 | 0.6338 |
| Precision | 0.5487 |
| Recall | 0.7502 |

The exploratory 90-day value model produced MAE £740.99, RMSE £3,737.25, and R² 0.2344 on the same untouched test snapshot. Treat it as prioritization support, not precise revenue forecasting.

# Windows setup

Complete the Windows/Python/PostgreSQL steps below before opening Tableau.
There is no bundled dataset that bypasses the pipeline.

Use the project at this exact location:

```text
D:\Project\online-retail-analytics
```

## 1. Open the correct folder

In VS Code:

```text
File > Open Folder > D:\Project\online-retail-analytics
```

Open `Terminal > New Terminal`. The PowerShell prompt must end with:

```text
PS D:\Project\online-retail-analytics>
```

## 2. Create the virtual environment

Run in the VS Code PowerShell terminal:

```powershell
py -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Confirm the environment:

```powershell
python -c "import pandas, sklearn, sqlalchemy, psycopg2; print('Environment ready')"
```

Expected:

```text
Environment ready
```

## 3. Create the PostgreSQL database

In pgAdmin 4:

1. Expand `Servers` and connect to the local PostgreSQL server.
2. Right-click `Databases`.
3. Select `Create > Database`.
4. Database: `online_retail_db`.
5. Owner: `postgres`.
6. Click `Save`.

The pipeline rebuilds the dedicated `retail` schema. Do not point `.env` to a database where you store unrelated objects inside that schema.

## 4. Create `.env`

Run in the VS Code terminal:

```powershell
Copy-Item .env.example .env
code .env
```

Replace only the password value:

```dotenv
PGHOST=localhost
PGPORT=5432
PGDATABASE=online_retail_db
PGUSER=postgres
PGPASSWORD=YOUR_ACTUAL_POSTGRES_PASSWORD
```

Never publish `.env`. The repository includes `.env.example`, which contains no real secret, and `.gitignore` blocks `.env`.

## Step 6 — export the single Tableau Public file

```powershell
python -m src.06_export_tableau_csv
```

Generated:

```text

```

two row types and record IDs, removes stale files from `data\outputs`, and then
writes this one final CSV. Therefore `data\outputs` contains exactly one usable
data file after a successful run.

The file contains two explicitly separated grains:

```text

record_type = Customer    →   5,878 rows for Dashboards 2 and 3
```

Do not delete the `record_type` worksheet filters described in the Tableau
guide. They prevent transaction and customer measures from being mixed.

## One-command execution — recommended

After PostgreSQL, `.env`, dependencies, and the raw workbook are ready:

```powershell

```

The command removes stale files from `data\outputs`, runs the same six numbered

    COUNT(*) AS transaction_rows,
    COUNT(DISTINCT invoice_no) AS orders,
    COUNT(DISTINCT customer_id) AS customers,
    MIN(invoice_date) AS first_transaction,
    MAX(invoice_date) AS last_transaction,

Then run:

SELECT
    COUNT(*) AS zero_or_negative_revenue_rows

Expected: `0`.

# Tableau architecture

```text
Dashboard 1: tableau_dashboard_dataset.csv, filtered to record_type = Transaction
Dashboard 2: tableau_dashboard_dataset.csv, filtered to record_type = Customer
Dashboard 3: tableau_dashboard_dataset.csv, filtered to record_type = Customer
```

All dashboards use the same physical CSV. Dashboard 1 uses transaction records
for Revenue, Orders, Customers, AOV, monthly trends, countries, and products.
Dashboards 2 and 3 use one row per customer for segments, risk, and value. This
prevents customer monetary and predicted value from being repeated across
hundreds of transaction rows.

Follow `dashboard\TABLEAU_PUBLIC_MANUAL_GUIDE.md` for the click-by-click build and `dashboard\TABLEAU_DASHBOARD_BLUEPRINT.md` for field placement and layout.

# Known error guide

| Error | Cause | Fix |
| --- | --- | --- |
| `fe_sendauth: no password supplied` | `.env` missing or password empty | Copy `.env.example` to `.env` and enter the real password |
| `transactions_revenue_check` on a £0.001 row | Old two-decimal schema/cleaning | Use this corrected package; rerun `01_clean_data`, then `02_load_postgresql` |
| Table appears empty under `public` | Project tables use the `retail` schema | Inspect `online_retail_db > Schemas > retail > Tables` |
| Mixed or inflated Tableau values | `record_type` filter is missing | Filter Dashboard 1 sheets to Transaction and Dashboard 2–3 sheets to Customer |
| Only one chart responds to Country/Year | Filter was applied to only one worksheet | Apply it to the selected Dashboard 1 worksheets |
| `relation retail.customer_features does not exist` | Modeling started before SQL features | Run `python -m src.03_build_sql_features` first |
| Tableau shows `EIRE` | Old clean output is being used | Rerun cleaning; the corrected pipeline standardizes it to `Ireland` |
